# Critical User Journey

Критический путь — сквозная задача пользователя, сбой которой делает справочник бесполезным. Каждая проверка проходит через UI, сервер и БД; отдельно те же правила проверяются API-клиентом.

| ID / цель | Исходные условия и шаги | Успех | Ветка отказа | Требования |
|---|---|---|---|---|
| CUJ-01 Найти телефон человека | Войти → выбрать «По имени» → ввести полное имя → «Найти» → выбрать нужного тезку | Показаны все точные совпадения и все телефоны; p95 поиска ≤500 мс на стенде | Пустой ввод — ошибка; нет совпадений — отдельное состояние; сбой — сообщение с возможностью повтора | UA-01…04, SR-01/03/04, RS-03 |
| CUJ-02 Узнать имя по номеру | Войти → «По телефону» → ввести полный RU номер с оформлением → найти | Показаны все контакты с этим номером, включая общий телефон | Неверный/не-RU номер — ошибка, не пустой результат; чужая сессия не раскрывает данные | CM-02/03, SR-02/03, UA-01 |
| CUJ-03 Сохранить и исправить контакт | Создать имя + 2 телефона → сохранить → обновить страницу → изменить один телефон → сохранить → выполнить поиск | Контакт и оба телефона сохранены, версия выросла; старый номер больше не ищется для этого контакта | Неверное поле откатывает весь запрос; при чужой правке 409 и явное обновление карточки | CM-01…04, RS-01 |
| CUJ-04 Удалить контакт | Открыть контакт → «Удалить» → сначала отменить → повторить и подтвердить → найти | После отмены данные есть; после подтверждения исчезли и карточка, и связи телефонов | Конкурентная правка запрещает удаление по старой версии; потерянный ответ проверяется чтением | CM-05, CM-04 |
| CUJ-05 Перенести справочник | Подготовить CSV → проверить → просмотреть отчет → применить → экспортировать → повторно импортировать экспорт | Все валидные контакты перенесены целиком; повтор дает 0 новых; тезки не объединены | Ошибка в последней строке не создает ни одного контакта; конфликт после проверки блокирует весь commit | DX-01…05, RS-02 |
| CUJ-06 Вернуть данные после сбоя | Сохранить контакт → аварийно перезапустить сервис; отдельно смоделировать потерю сервера → оператор восстанавливает копию → оба пользователя входят и ищут | Обычный сбой не теряет подтвержденную запись; disaster restore соответствует RPO/RTO | Поврежденная копия обнаружена, выбран предыдущий проверенный снимок; нарушение RPO/RTO фиксируется как провал приемки | RS-01/04, UA-01 |

CUJ-01 и CUJ-02 — главные бизнес-пути; CUJ-03…05 обеспечивают актуальность и переносимость; CUJ-06 — эксплуатационный путь сохранности. Для каждого в отчете нужны фактический результат, дата МСК, версия сборки, данные стенда и ссылка на доказательство. Заранее помечать сценарии пройденными запрещено.
