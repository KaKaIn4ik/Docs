# Нормативный контракт CSV

## Формат и идентичность
Файл UTF-8, допускается BOM при чтении; экспорт содержит BOM для удобства открытия в Excel. Разделитель — запятая, заголовок строго `contact_id,name,phone` в этом порядке, без дополнительных колонок. Строки — CRLF при экспорте, CRLF/LF при импорте. Кавычки и запятые экранируются стандартным CSV quoting: поле в двойных кавычках, внутренняя кавычка удваивается. Пустые строки после заголовка запрещены. Файл только с заголовком — допустимый импорт без изменений.

Одна строка содержит один телефон. Все строки с одним contact_id образуют контакт, даже если идут не подряд. UUID обязателен: это позволяет отличать тезок и безопасно повторять перенос. Экспорт сохраняет UUID. При подготовке файла вручную UUID создается один раз на человека и повторяется для его телефонов; произвольные номера строк вместо UUID не принимаются. UI показывает это правило и скачиваемый шаблон с объяснением, что идентификаторы примера нужно заменить.

В группе от 1 до 10 уникальных после нормализации телефонов, одно и то же имя после NFC/trim (регистр сохраняется). Повтор номера внутри группы — ошибка. У разных групп допустимы одинаковые имена и телефоны. Импорт не объединяет людей по имени или номеру. Предметная валидация полностью совпадает с docs/api.md.

## Алгоритм, наблюдаемый пользователем
1. Пользователь выбирает файл до 1 GiB (1 073 741 824 байт).
2. Система проверяет кодировку, структуру, до 1 000 000 строк данных и до 100 000 групп UUID; затем все поля и группы. При нарушении размера/числа строк обработка может остановиться сразу; при обычных ошибках строк проверяется весь файл. Отчет считает все ошибки и показывает первые 1000 в порядке строки/поля, с признаком усечения.
3. Для существующего UUID сравниваются сохраненное имя (NFC/trim, регистр значим) и множество канонических телефонов. Совпадение — пропуск, различие — конфликт всего файла. Проверяется доступная емкость с учетом только новых UUID.
4. Если ошибок нет, UI показывает число новых и пропущенных контактов и срок подтверждения 30 минут. На сервере хранится неизменяемый проверенный файл, а не повторно присланный клиентом набор.
5. Пользователь нажимает «Применить». В одной транзакции повторяются проверки конфликтов и емкости на актуальном состоянии; сохраняются все новые контакты и итог импорта. Любая ошибка откатывает все новые контакты.
6. Успех показывает фактические created_count/skipped_count. Если другой клиент успел создать полностью совпадающие UUID, итоговые счетчики могут отличаться от предварительных. Повтор подтверждения не выполняет импорт повторно.

Импорт только добавляет или пропускает; для изменений служит редактирование контакта. Удаленные контакты при последующем импорте старого файла будут созданы заново — это явное действие пользователя. История удаленных UUID не хранится. Импорт не является восстановлением полной базы: не восстанавливает пароли, версии, даты и сеансы.

## Экспорт и табличные редакторы
Экспортирует все контакты, сортировка UUID ASC, внутри контакта phone ASC. Данные читаются в одном согласованном снимке; параллельные изменения после начала экспорта в него не попадают. Импорт экспорта в ту же неизмененную базу добавляет 0 контактов.

Для снижения риска выполнения формул при открытии CSV в табличном редакторе каждое экспортируемое значение name/phone, начинающееся с =, +, -, @, TAB или CR, получает один ведущий апостроф. Значение, уже начинающееся с апострофа, также получает еще один. UUID не экранируется. При импорте апостроф снимается ТОЛЬКО когда после него находится один из перечисленных символов или второй апостроф. Так +79991234567 выгружается как '+79991234567, а имя с исходным апострофом не теряется. Это правило является частью формата; обычное заключение поля в CSV-кавычки его не заменяет. Самовольное удаление апострофов редактором нарушает обратимость; проверка выполняется на байтах исходного экспорта. Для телефонов при ручном редактировании рекомендуется текстовый тип столбца.

CSV не хранится в журналах; временные файлы доступны только сервису и удаляются после commit либо истечения 30 минут, с периодом очистки не более 15 минут. При commit сохраняются итог и хеш, содержимое файла для повтора не требуется.

## Размер максимального переноса
Лимит 1 GiB выбран так, чтобы собственный экспорт максимальной допустимой базы помещался обратно в импорт. Консервативная верхняя оценка одной строки: UUID 36 + разделители 2 + имя (200 кодовых точек, до 800 байт UTF-8 и до 200 дополнительных кавычек плюс обрамление/апостроф, всего ≤1003) + телефон с апострофом 13 + CRLF 2 = ≤1056 байт. На миллион строк это ≤1 056 000 000 байт плюс короткий заголовок и BOM, меньше 1 073 741 824. При изменении лимитов модели расчет пересматривается. Произвольный внешний CSV с чрезмерным количеством оформления/пробелов все равно может превышать лимит и отклоняется.

При потере ответа первой проверки файла разрешена повторная загрузка как нового батча: создание батча никогда не применяет контакты. Старый неподтвержденный батч автоматически истекает. При потере ответа commit используется известный import_id, повторная загрузка не требуется.

Номер line в отчете — номер логической CSV-записи: заголовок имеет номер 1, первая запись данных — 2. Встроенные переводы строк внутри quoted-поля не увеличивают номер записи; для name они затем отклоняются предметной валидацией. При неразбираемой CSV-структуре указывается номер текущей логической записи.
