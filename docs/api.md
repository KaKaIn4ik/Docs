# Нормативный контракт HTTP API v1

Этот документ детализирует CM, SR, DX и UA. Все пути относительны к /api/v1. HTTPS обязателен. JSON — UTF-8; неизвестные поля и параметры отклоняются. Предметные правила одинаковы для UI, API и импорта. Идентификаторы — UUID в нижнем регистре со стандартными дефисами; сервер нормализует допустимый регистр UUID. Числа версий — положительные целые.

## Нормализация
**Имя:** Unicode NFC, затем удаление Unicode-пробелов с краев. Исходный регистр и внутренние пробелы сохраняются для отображения. Ключ поиска — casefold от сохраненного имени. Управляющие символы Unicode категории Cc, включая табуляцию и перевод строки, запрещены. Форматирующие символы Cf также запрещены. Лимит 200 кодовых точек применяется после NFC/trim. Е/ё, дефисы, апострофы, порядок слов и внутренние пробелы не заменяются.

**Телефон:** вход — строка до 64 символов; разрешены только ASCII-цифры, ASCII-пробел, +, -, (, ). Скобки должны быть парными, плюс допустим только первым непробельным символом. После удаления оформления принимаются +7XXXXXXXXXX, 7XXXXXXXXXX или 8XXXXXXXXXX; последние два преобразуются в +7XXXXXXXXXX. Без кода, с буквами, добавочным, другим числом цифр и не-RU регионом ввод отклоняется. Затем библиотека phonenumbers проверяет валидность номера и регион RU, а не только префикс +7. Это проверка метаданных нумерации, не звонок абоненту. Версия метаданных фиксируется зависимостями; при обновлении существующие контакты автоматически не переписываются. Экспорт существующих сохраненных номеров разрешен; новый ввод проверяется актуальной зафиксированной версией. Изменение правил — отдельное изменение спецификации.

Повторяющиеся канонические номера в одном контакте — 422 duplicate_phone, не молчаливое удаление дубликата. Порядок телефонов не имеет значения: ответы содержат их в лексикографическом порядке.

## Представления
Контакт: id (UUID), name (строка), phones (массив строк), version (целое), created_at и updated_at (RFC3339 UTC с Z). Поля id/version/даты серверные, кроме клиентского id при POST для безопасного повтора. Пример контакта: id=4b306826-cb7b-4cc8-a826-c2268c4ae3aa, name=Иван Иванов, phones=[+79991234567], version=1. Пример номера иллюстративный; приемочные фикстуры должны соответствовать закрепленным метаданным.

Список: results (массив контактов), count (все совпадения), limit, offset. Параметры limit: целое 1–100, по умолчанию 50; offset: целое ≥0, по умолчанию 0. Сортировка UUID ASC. count и страница читаются в одном снимке БД. Между запросами страниц возможны изменения набора; замороженная сессия поиска не обещается.

Ошибка: error содержит code (стабильный машинный код), message (понятный русский текст), fields (словарь ошибок полей, иначе пустой), request_id. Ошибка CSV дополнительно содержит total_errors и errors (до 1000 элементов с line, field, code, message), truncated. Строки файла не отражаются целиком.

## Операции
| Метод и путь | Вход | Успех | Ошибки предметной области |
|---|---|---|---|
| GET /session | Без тела; доступен до входа, выдает CSRF-cookie | 200: authenticated и username (null до входа) | 503 |
| POST /session | username, password; CSRF | 200: username; устанавливает cookie сессии | 401 invalid_credentials, 429 login_rate_limited |
| DELETE /session | Сессия и CSRF | 204; удаляет сессию | 401, 403 |
| GET /contacts | limit, offset; допускает ровно один фильтр name или phone | 200: список | 422 invalid_query/invalid_name/invalid_phone/unsupported_region |
| GET /contacts/{id} | UUID | 200: контакт | 404 not_found |
| POST /contacts | id, name, phones; id обязателен и генерируется клиентом | 201: контакт, Location | 409 id_conflict/capacity_exceeded, 422 |
| PUT /contacts/{id} | name, phones, version; полная замена изменяемых полей | 200: контакт новой версии | 404, 409 version_conflict, 422 |
| DELETE /contacts/{id} | version в JSON-теле | 204 | 404, 409 version_conflict, 422 |
| POST /imports | multipart: file | 201: import_id, state=validated, created_count, skipped_count, expires_at | 413, 422 invalid_csv, 409 import_conflict/capacity_exceeded |
| POST /imports/{id}/commit | Без тела; подтверждение | 200: import_id, state=committed, created_count, skipped_count | 404, 409 import_conflict/capacity_exceeded, 410 import_expired |
| GET /imports/{id} | Только свой import_id | 200: состояние и итоговые счетчики | 404, 410 |
| GET /export | Без параметров | 200: text/csv, attachment phonebook.csv | 503 |

GET /contacts без фильтра — просмотр общего списка. При наличии фильтра пустое значение запрещено. Одновременные name и phone запрещены. Других фильтров, частичного поиска и комбинирования условий нет. Невалидный UUID пути дает 422 invalid_id; корректный отсутствующий — 404.

**Повтор создания:** повтор POST с существующим id и полностью теми же сохраненным именем и множеством телефонов возвращает 200 с текущим контактом, не создает копию. Сравнение имени — NFC/trim с сохраненным регистром. Другие данные при том же id дают 409 id_conflict. Клиент после неопределенного исхода PUT/DELETE читает UUID; старую версию автоматически не заменяет актуальной. Повтор DELETE отсутствующего UUID дает 404.

**Импорт:** сохраняется проверенный файл, хеш, владелец, отчет и срок 30 минут. Доступ только автору. GET после истечения неподтвержденного импорта дает 410; неизвестный/чужой id — 404. Завершенный результат хранится 7 суток и доступен повторным GET/commit с тем же итогом; затем 410. Ошибка применения оставляет валидированный импорт доступным до исходного срока; при конфликте требуется исправить файл и создать новый импорт. Полный протокол — docs/csv.md.

## Общие HTTP-правила
401 — нет/истекла сессия; 403 — ошибка CSRF; 400 — некорректный JSON; 413 — слишком большое тело; 415 — неверный Content-Type; 422 — поля/запрос; 409 — конфликт; 500 — неожиданный сбой с request_id без деталей; 503 — БД недоступна. JSON-запросы до 64 KiB, кроме CSV. Порядок проверок: размер/тип/синтаксис → сессия/CSRF → поля → существование/версия/емкость → транзакция. GET /session и POST /session — исключения из требования уже выполненного входа; POST по-прежнему требует CSRF. Служебные health probes не выдают данные контактов.

CSRF-cookie получается через GET /session; значение передается заголовком X-CSRFToken для POST/PUT/DELETE, включая вход. Сессия — HttpOnly, Secure, SameSite=Lax; CSRF-cookie не HttpOnly для браузерного клиента. Сессионная cookie не продлевается автоматически, истекает через 8 часов после входа. Программный клиент хранит cookie и CSRF так же, как браузер. Выдача API-ключей и CORS для чужих сайтов не входят в v1. Все ответы с контактами, поиском, импортом и экспортом имеют Cache-Control: no-store.

## Истечение и очистка импорта
Срок неподтвержденного батча проверяется по серверным часам после получения блокировок DirectoryState и ImportBatch, до начала применения. Если now ≥ expires_at, commit возвращает 410. Если commit допущен до срока, он может завершиться после expires_at в пределах общего таймаута; его не прерывают только из-за наступления срока. Параллельный commit того же батча ждет блокировку, затем возвращает сохраненный итог.

Очистка неподтвержденного батча сначала получает те же блокировки в том же порядке, проверяет состояние и срок, помечает expired и фиксирует состояние, затем удаляет файл. Очистка не удаляет файл работающего commit; подтвержденный/истекший батч больше не читается для применения. Сервисный проход повторяет физическое удаление при ошибке. Проверка SHA256 и чтение файла выполняются при удержании блокировки батча.

Успешный GET /imports/{id} возвращает import_id, state, created_count, skipped_count, expires_at и committed_at. Для validated счетчики предварительные и committed_at=null; для committed счетчики итоговые, committed_at — момент UTC, expires_at — срок хранения результата (7 суток от коммита). Ответ POST /imports содержит те же поля с committed_at=null. Успешный commit возвращает тот же полный объект состояния. Для expired возвращается ошибка 410 по общему формату, не успешный объект.
