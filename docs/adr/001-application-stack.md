# ADR-001: Python-приложение и готовая СУБД

Дата: 26.10.2026. Статус: принято в проектной спецификации v1.0.

## Контекст
Нужно новое приложение с UI и API для двух пользователей и 100000 контактов. Пользователь выбрал Python и телефонный справочник вместо собственного движка.

## Решение
Python 3.12 + Django 5.2 LTS, PostgreSQL 18; UI на серверных шаблонах, HTTP JSON API в том же приложении. Patch-версии фиксируются перед реализацией.

## Альтернативы
SQLite проще в эксплуатации, но PostgreSQL выбран для явных транзакций, блокировок и штатного внешнего резервирования. FastAPI + отдельные auth/ORM/UI-компоненты допустим, но требует больше сборки компонентов. Собственный движок — лишняя область риска для данного задания.

## Последствия
Одно развертывание и общий слой правил; нужен оператор PostgreSQL и резервирования. Не утверждается, что PostgreSQL необходим для 100000 записей: это инженерный выбор, а не предел SQLite.

## Когда пересматривать
Встраиваемое автономное приложение, запрет серверной СУБД или существенное изменение окружения.

## Основания
F-01, F-04, U-02; решения D-01.
