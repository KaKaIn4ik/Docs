# Proposal: телефонный справочник

## Why
Двум пользователям нужен общий надежный справочник, чтобы находить имена по номеру и телефоны по имени, поддерживать данные вручную и переносить их через CSV. Неопределенные слова исходного задания превращаются в критерии приемки: целевая емкость, задержка поиска, атомарность изменений и восстановление.

## What Changes
- Создается новое приложение на Python с браузерным интерфейсом и HTTP JSON API.
- Вводятся контакты с одним именем и несколькими российскими телефонами.
- Добавляются точный поиск после нормализации, CRUD и защита от потери чужих изменений.
- Добавляются CSV-импорт с полной предварительной проверкой и экспорт.
- Вводятся две учетные записи, общий доступ, ежедневные резервные копии.
- Цели: 100 000 контактов; p95 поиска ≤500 мс при двух одновременных пользователях; восстановление после потери сервера ≤1 часа, потеря данных ≤24 часов при исправных копиях.

## Capabilities
### New Capabilities
- `contact-management`: контакты, правила полей, создание, изменение и удаление.
- `exact-search`: поиск по имени или телефону с полным совпадением нормализованного значения.
- `data-exchange`: проверяемый CSV-импорт и обратимый экспорт.
- `user-access`: две учетные записи, общие данные, браузер и API.
- `reliable-storage`: сохранность, емкость, производительность, резервирование и время.
### Modified Capabilities
Нет: проект новый, существующих спецификаций нет.

## Impact
Новый сервер, PostgreSQL, браузерный UI, HTTP API, хранилище копий и эксплуатационный регламент. Контакты — общие для приложения, а не пользовательские. Внешние интеграции и Android-код не затрагиваются.

Вне первой версии: собственный движок БД, публичный интернет, регистрация, роли с разными правами, проверка владения номером, SMS, нечеткий/частичный поиск, слияние контактов, восстановление удаленного контакта одной кнопкой, Excel XLSX, мобильное приложение, кластер высокой доступности.
