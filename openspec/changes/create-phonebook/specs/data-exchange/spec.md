# Spec Delta

## Purpose
Перенос контактов через единый CSV-контракт с предварительной проверкой и атомарным применением.

## ADDED Requirements

### Requirement: DX-01 CSV-контракт
Система SHALL импортировать и экспортировать CSV по docs/csv.md: UTF-8, разделитель запятая, одна строка на телефон, поля contact_id,name,phone. Порядок и группировка имеют документированную семантику.

#### Scenario: Несколько телефонов
- **WHEN** импортируются две строки с одним contact_id, одинаковым именем и разными телефонами
- **THEN** создан один контакт с двумя телефонами.

#### Scenario: Разное имя в группе
- **WHEN** строки одного contact_id имеют разные имена после NFC и trim
- **THEN** файл отклонен с указанием строк, данные не изменены.

### Requirement: DX-02 Полная предварительная проверка
Система SHALL проверять весь CSV до предложения применить импорт. Ошибка хотя бы одной строки запрещает применение всего файла. Лимиты: 1 GiB, 100 000 контактов, 1 000 000 строк данных.

#### Scenario: Ошибка в конце
- **WHEN** последняя строка содержит недопустимый телефон
- **THEN** выдан отчет с номером строки и кодом ошибки; ни один контакт не добавлен.

#### Scenario: Превышение
- **WHEN** файл превышает 1 GiB
- **THEN** ответ 413 до загрузки в память целиком, импорт не создается.

### Requirement: DX-03 Импорт без дубликатов
Система SHALL создавать отсутствующие UUID, пропускать полностью совпадающие контакты и отклонять существующий UUID с отличающимся содержимым. Импорт не изменяет и не удаляет существующие контакты.

#### Scenario: Повтор
- **WHEN** один и тот же валидный файл применен повторно
- **THEN** все совпадающие UUID пропущены; новые контакты не созданы.

#### Scenario: Коллизия идентичности
- **WHEN** существующий UUID имеет другое имя или набор телефонов
- **THEN** импорт целиком отклонен с import_conflict; существующий контакт не изменен.

### Requirement: DX-04 Подтверждение и атомарность
Система SHALL применять только проверенный неизменяемый файл после явного подтверждения. Перед коммитом повторно проверяются актуальные конфликты и емкость. При ошибке откатывается весь импорт; повтор подтверждения завершенного импорта возвращает прежний результат.

#### Scenario: Изменение между этапами
- **WHEN** после проверки другой пользователь создал конфликтующий UUID
- **THEN** применение получает 409, импорт не добавляет ни одного контакта.

#### Scenario: Сбой
- **WHEN** соединение потеряно во время применения
- **THEN** повтор по import_id либо возвращает завершенный результат, либо безопасно применяет еще не завершенную операцию ровно один раз.

### Requirement: DX-05 Экспорт
Система SHALL экспортировать весь справочник из согласованного снимка в обратимом формате DX-01, включая UUID. Экспорт требует авторизации и не включает пароли, сессии и служебные данные.

#### Scenario: Круговой перенос
- **WHEN** экспортирован справочник и файл импортирован в пустой экземпляр с теми же правилами номеров
- **THEN** восстановлены те же UUID, имена и наборы телефонов; версии и даты создаются заново.

#### Scenario: Нет контактов
- **WHEN** экспортируется пустой справочник
- **THEN** скачивается CSV только с заголовком.
