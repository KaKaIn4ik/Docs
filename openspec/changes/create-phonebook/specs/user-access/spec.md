# Spec Delta

## Purpose
Единый защищенный доступ двух пользователей к общему справочнику через браузер и программный интерфейс.

## ADDED Requirements

### Requirement: UA-01 Две учетные записи
Система SHALL предоставлять две индивидуальные учетные записи с паролями и равными правами на общий справочник. Самостоятельная регистрация отсутствует; создание и сброс пароля выполняет оператор.

#### Scenario: Общие данные
- **WHEN** первый пользователь создал контакт, второй вошел со своей учетной записью
- **THEN** второй может прочитать, изменить и удалить этот контакт.

#### Scenario: Чужой доступ
- **WHEN** неавторизованный клиент обращается к контактам, поиску или CSV
- **THEN** API возвращает 401, UI направляет на вход; данные не раскрываются.

### Requirement: UA-02 UI
Система SHALL предоставлять русскоязычные страницы входа, списка/поиска, создания/редактирования, импорта и экспорта. Ошибки, пустой результат, загрузка и конфликт версий имеют отдельные состояния по docs/ui.md.

#### Scenario: Создание из браузера
- **WHEN** пользователь заполнил форму и получил успешное сохранение
- **THEN** открыта карточка сохраненного контакта с актуальной версией; показано подтверждение.

#### Scenario: Сбой сохранения
- **WHEN** сервер не ответил
- **THEN** форма сохраняет ввод, сообщает о неизвестном результате; успех не показывается.

### Requirement: UA-03 Программное API
Система SHALL предоставлять версионированный HTTP JSON API /api/v1 по docs/api.md для авторизации, CRUD, поиска и CSV-обмена. UI и API используют одинаковые правила предметной области.

#### Scenario: Одинаковая проверка
- **WHEN** один недопустимый телефон отправлен через UI и API
- **THEN** обе операции отклонены с одним предметным кодом ошибки.

#### Scenario: Неизвестное поле
- **WHEN** клиент передал поле, отсутствующее в контракте
- **THEN** возвращается 422 unknown_field без частичного сохранения.

### Requirement: UA-04 Безопасность сеанса
Система SHALL защищать UI и API по HTTPS в локальной сети; хранить только хеши паролей, использовать серверные сессии и CSRF-защиту изменяющих запросов. Сеанс истекает через 8 часов и немедленно прекращается при выходе.

#### Scenario: CSRF
- **WHEN** клиент с сессией отправил изменение без корректного CSRF-токена
- **THEN** получает 403 csrf_failed; данные не изменены.

#### Scenario: Выход
- **WHEN** пользователь завершил сеанс и повторил запрос со старой cookie
- **THEN** получает 401.

#### Scenario: Подбор пароля
- **WHEN** с одной пары IP/имя выполнено 5 неудачных входов за 15 минут
- **THEN** дальнейшие входы для этой пары блокируются на 15 минут с 429; пароль и наличие учетной записи не раскрываются.
