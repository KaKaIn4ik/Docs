# Spec Delta

## Purpose
Управление общими контактами с однозначными правилами имени, телефонов и конкурентного изменения.

## ADDED Requirements

### Requirement: CM-01 Модель контакта
Система SHALL хранить UUID контакта, имя, от 1 до 10 разных телефонов, версию и даты создания/изменения. Имя после NFC и удаления крайних пробелов содержит 1–200 Unicode-символов; управляющие символы запрещены.

#### Scenario: Создание
- **WHEN** пользователь сохраняет допустимое имя и два разных допустимых телефона
- **THEN** создан один контакт версии 1; чтение возвращает оба телефона и серверные даты.

#### Scenario: Недопустимое поле
- **WHEN** имя пусто, длиннее 200 символов либо список телефонов пуст или длиннее 10
- **THEN** запрос отклонен с ошибками полей, контакт не создан.

### Requirement: CM-02 Российские телефоны
Система SHALL применять единый контракт нормализации из docs/api.md ко всем операциям. Хранятся только допустимые для региона RU номера в каноническом формате +7 и 10 цифр. Номер не подтверждает владение или доступность абонента.

#### Scenario: Эквивалентное оформление
- **WHEN** введены +7 (999) 123-45-67 и 8 999 123 45 67
- **THEN** они нормализованы в +79991234567; повтор номера внутри одного контакта отклонен.

#### Scenario: Чужой регион
- **WHEN** введен номер Казахстана, начинающийся с +7
- **THEN** запрос отклонен как unsupported_region, несмотря на общий код +7.

#### Scenario: Недопустимый ввод
- **WHEN** введен короткий, международный не-RU номер или номер с добавочным
- **THEN** запрос отклонен без изменения данных.

### Requirement: CM-03 Совпадающие данные разных людей
Система SHALL разрешать одинаковые имена и общий номер у разных контактов. Единственным идентификатором личности в приложении является UUID; имя и телефон сами по себе не определяют контакт.

#### Scenario: Два тезки
- **WHEN** создаются два контакта с одним именем
- **THEN** оба получают разные UUID и доступны отдельно.

#### Scenario: Общий телефон
- **WHEN** два контакта содержат один номер
- **THEN** оба сохраняются; поиск по номеру возвращает оба контакта.

### Requirement: CM-04 Конкурентное изменение
Система SHALL обновлять контакт атомарно только при совпадении переданной версии с текущей; при успехе версия увеличивается на 1. Имя и весь набор телефонов изменяются одной операцией.

#### Scenario: Конфликт
- **WHEN** два пользователя прочитали версию 3 и первый уже сохранил версию 4
- **THEN** второе сохранение версии 3 получает 409 version_conflict; чужие изменения не перезаписаны.

#### Scenario: Неверный новый телефон
- **WHEN** изменение содержит допустимое имя и недопустимый телефон
- **THEN** не изменены ни имя, ни телефоны, ни версия.

### Requirement: CM-05 Удаление
Система SHALL удалять контакт вместе с его телефонами только после подтверждения в UI и проверки версии на сервере. Отмена подтверждения не изменяет данные.

#### Scenario: Удаление
- **WHEN** подтверждено удаление существующего контакта с актуальной версией
- **THEN** контакт и телефоны исчезают; чтение UUID возвращает 404.

#### Scenario: Устаревшая версия
- **WHEN** после открытия подтверждения контакт изменен другим пользователем
- **THEN** удаление получает 409, актуальный контакт сохраняется.
